# Deploying iPOSa to Render

Render has no native PHP runtime, so iPOSa runs as a **Docker web service** plus a **managed Postgres** database. Everything is described in [`render.yaml`](../render.yaml) (a Render Blueprint).

## What gets deployed

| Piece | File | What it does |
|---|---|---|
| Image | `Dockerfile` | Stage 1 builds Vite/Tailwind assets with Node 22. Stage 2 is PHP 8.4-FPM (pgsql, mysql, zip, intl, bcmath, opcache) + nginx + supervisord, with `composer install --no-dev` |
| Start script | `docker/start.sh` | Fixes the `APP_KEY` prefix, sets `APP_URL` from Render, caches config/routes/views, **runs migrations**, creates the operator account, optionally seeds the demo, then starts supervisord |
| Processes | `docker/supervisord.conf` | php-fpm, nginx (on Render's `$PORT`), and `schedule:work` (runs the daily `businesses:mark-overdue`) |
| Web server | `docker/nginx.conf.template` | Laravel front controller, 1-year cache on `/build/*`, security headers |
| Blueprint | `render.yaml` | Web service + Postgres in Singapore, all environment variables |

Health check: `GET /up` (Laravel's built-in route).

## First deploy

1. **Push this branch to GitHub** (Render deploys from a Git repo).
2. Render dashboard → **New → Blueprint** → pick the repo. Render reads `render.yaml`.
3. Fill in the values Render asks for (the `sync: false` ones):

   | Variable | Example | Why |
   |---|---|---|
   | `SUPER_ADMIN_EMAIL` | `you@yourdomain.com` | Your platform-operator login |
   | `SUPER_ADMIN_PASSWORD` | 12+ characters | Only used to create the account the first time |
   | `MAIL_HOST` | `smtp-relay.brevo.com` | Sign-up verification and staff invites send email |
   | `MAIL_USERNAME` / `MAIL_PASSWORD` | from your mail provider | |
   | `MAIL_FROM_ADDRESS` | `hello@yourdomain.com` | Must be a sender your provider has verified |
   | `BILLING_GCASH_NUMBER` | `0917 123 4567` | Shown to owners in Settings → Plan & billing |
   | `BILLING_BANK` | `BPI · 1234-5678-90 · Your Name` | Same |

4. Click **Apply**. The first build takes a few minutes. When the service shows **Live**, open its `https://…onrender.com` URL.
5. Log in with `SUPER_ADMIN_EMAIL` → you land on the platform console. Shops sign up at `/register`.

`APP_KEY` is generated by Render (`generateValue`), and `APP_URL` defaults to the service's public URL. Set `APP_URL` yourself only after adding a custom domain.

## Want the demo data online?

Set `SEED_DEMO_DATA=true` and redeploy. It loads "Kape't Burger" with 14 days of activity. (The 17 extra platform shops use Faker, a dev-only package, so they're seeded locally only.) Demo logins use the password **`password`** (`admin@gmail.com`, `staff@gmail.com`), so **set it back to `false` and don't use it for a real shop**. Seeding is skipped when the demo shop already exists.

## Every later deploy

Pushing to the branch redeploys automatically (`autoDeploy: true`). On each start the container runs pending migrations, re-caches config, and leaves the operator's password alone (`app:ensure-super-admin` only creates or promotes).

Reset the operator password from a Render Shell (paid instances):

```bash
php artisan app:ensure-super-admin --email=you@yourdomain.com --password='new-long-password' --reset-password
```

## Plans and limits to know about

| Item | Free tier | For real shops |
|---|---|---|
| Web service | Sleeps after ~15 min idle; the first request then takes ~1 minute | **Starter**: always on (a cashier can't wait a minute mid-rush) |
| Postgres | Deleted 30 days after creation | **Basic-256mb** or higher, with backups |
| Email | Some providers block ports 25/465/587 from free hosts; port **2525** is set by default (Brevo, Mailgun, SendGrid support it) | Same |

Change `plan:` in `render.yaml` (or in the dashboard) when you move off the free tier.

## Custom domain

Render dashboard → service → **Settings → Custom Domains** → add `app.iposa.me`, create the DNS record Render shows, then set `APP_URL=https://app.iposa.me` and redeploy. HTTPS certificates are automatic.

## Troubleshooting

| Symptom | Check |
|---|---|
| Deploy fails at "Waiting for the database" | The database is still being created. Redeploy after it shows **Available** |
| 500 error on every page | Render logs. Usually a missing env var; `APP_DEBUG=false` hides details from visitors |
| Verification email never arrives | `MAIL_*` values; the provider's sending log; the sender address must be verified. Meanwhile nobody is stuck: the verify page offers **“Ask an agent to verify me”**, and you verify them in the platform console under **Verifications** (one button) |
| Sign-up is slow, then says the email couldn't be sent | SMTP is blocked or wrong. `MAIL_TIMEOUT` (default 10 s) keeps it short. Owners use the agent fallback, and cashiers can be added with a password set by the owner |
| Links or redirects use `http://` | `APP_URL` must start with `https://`. Proxies are trusted in `bootstrap/app.php` |
| Owners see "trial ended" too early | Server time is correct; the app uses `APP_TIMEZONE=Asia/Manila` |

## Run the production image locally

```bash
docker build -t iposa .
docker network create iposa-net
docker run -d --name iposa-pg --network iposa-net -e POSTGRES_DB=iposa -e POSTGRES_USER=iposa -e POSTGRES_PASSWORD=secret postgres:16-alpine
docker run --rm -p 10000:10000 --network iposa-net \
  -e APP_KEY="$(php artisan key:generate --show)" -e APP_URL=http://localhost:10000 \
  -e DB_CONNECTION=pgsql -e DB_HOST=iposa-pg -e DB_DATABASE=iposa -e DB_USERNAME=iposa -e DB_PASSWORD=secret \
  -e SESSION_SECURE_COOKIE=false -e SEED_DEMO_DATA=true iposa
```

Then open http://localhost:10000.
